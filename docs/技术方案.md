## 3. SSH 技术方案

### 3.1 连接能力

- 支持密码认证与私钥认证。
- 私钥既支持 legacy 的“按服务器保存”，也支持密钥中心模式（`ssh_key_profiles` + `sshKeyId`）。
- `SSHService.connectViaJumpHosts` 使用逐级 `forwardLocal` 建立跳板机链路。
- `ServerConfig` 已包含 `jumpServerIds` 字段，跳板链拓扑由仓库层解析。

### 3.2 主机指纹方案

- 首次连接时通过回调走 TOFU。
- 一旦接受，`KnownHostRepository` 将 `host:port -> fingerprint + algorithm` 持久化。
- 后续连接若算法或指纹不匹配，直接判定为主机校验失败。

### 3.3 长连接与重连

- SSH KeepAlive 间隔由 `AppLimits.keepAliveInterval` 统一控制，当前为 15 秒。
- 自动重连由 `ServerConnectionController` 实现：
  - 最大重试次数: `5`
  - 基础退避: `1000ms`
  - 最大退避: `15000ms`
- 网络恢复后会根据 `NetworkMonitorService` 事件触发重连。
- 重连成功后可恢复可重建的 Shell 与 `autoStart` 隧道。

### 3.4 端口转发

- 支持本地转发和远程转发配置。
- AI HTTP 模式并不直接依赖 Flutter 端原生网络穿透，而是通过 `SshPortForwardService` 在本地监听随机端口，再桥接到远端 loopback 端口。

## 4. AI 集成技术方案

### 4.1 总体策略

- 优先使用远端 HTTP API，原因是：
  - 更稳定的结构化响应
  - 更容易支持流式输出与中断
  - 更适合会话上下文复用
- 若 HTTP 不可用，则自动回退到 SSH execute 或 PTY 模式。

### 4.2 OpenCode

- 检测方式: `which opencode`。
- 首选模式: `http`。
- 自动启动方式: 远端执行 `opencode serve`，并在环境变量中写入 `OPENCODE_SERVER_PASSWORD`。
- 认证方式: HTTP Basic Auth，用户名固定为 `opencode`。
- 回退路径: `pty` + `--format json`。

### 4.3 OpenClaw

- 检测方式: `which openclaw`。
- 首选模式: `http`。
- 自动启动方式:
  - 先执行 `openclaw config set gateway.http.endpoints.chatCompletions.enabled true`
  - 再启动 `openclaw gateway`
- 认证方式: `Authorization: Bearer <OPENCLAW_GATEWAY_PASSWORD>`。
- 回退路径: `execute` 优先，必要时 `pty`。

### 4.4 AI 会话与缓存

- `AIConversationRepository` 保存对话与消息。
- `AIConversation.sessionContext` 记录远端会话上下文，例如 OpenClaw session key。
- `AIToolDetectionCacheService` 保存：
  - 最近一次完整检测结果
  - 最近一次真实成功的工具 + 模式
- 目的不是“离线可用”，而是减少重复探测和启动开销。

## 5. 存储与安全方案

### 5.1 Hive

- 保存非敏感结构化数据：
  - 服务器配置
  - 密钥资料元数据
  - 已知主机
  - 端口转发配置
  - 快捷命令
  - 应用设置
  - AI 工具配置
  - AI 对话与消息
  - AI 工具检测缓存

### 5.2 `flutter_secure_storage`

- 保存敏感数据：
  - SSH 密码
  - 私钥明文
  - 私钥口令
  - OpenCode server 密码
  - OpenClaw gateway 密码

### 5.3 Android 存储兼容性

- 当前使用 v9 兼容的 cipher 组合，并开启 `migrateOnAlgorithmChange`。
- 这是为了兼容升级到 `flutter_secure_storage 10` 后的旧设备数据，避免凭证读取失败。

## 6. 工程校验方案

### 6.1 本地统一入口

```bash
dart run tool/verify.dart analyze
dart run tool/verify.dart test
dart run tool/verify.dart build-apk
```

### 6.2 `verify.dart` 做的事情

1. `flutter pub get`
2. `build_runner build --delete-conflicting-outputs`
3. 校验生成文件是否已提交
4. 执行静态检查 / 测试 / Release APK 构建

### 6.3 CI

- GitHub Actions 已接入 `analyze`、`test`、`build` 三条流水线。
- `build` 任务带 Gradle 缓存与 Android licenses 处理。
